## 2. 下一步优先级

### P0-4：PostgreSQL 只读浏览 + 数据库级管理（建议下一个里程碑）

**PostgreSQL 浏览**

- 后端方言抽象：标识符引用（反引号 → 双引号）、分页 SQL（`LIMIT/OFFSET` 相同）、
  schema 层级（PG 的 schema 与 MySQL 的 database 语义不同）；
- 元数据：`pg_database` / schema / 表 / 列 / 主键与唯一索引（行标识复用现有逻辑）；
- 前端能力矩阵：`capabilities.js` 打开 PG 的 `browse`，资源树显示 schema 层级；
- 测试：PG 方言 SQL 构建单测；集成测试依赖 Testcontainers（见 M2）。

**数据库级管理**

- 开发环境总览：本工具已保存哪些连接、连到哪些库（不泄露密码）；
- 新建/删除数据库（危险操作二次确认 + 白名单校验）；
- 数据目录展示与“备份提示”（只读展示 `data/` 位置，不做浏览器内备份/下载）。

### P1-2：表格编辑增强

- 整行编辑弹窗（一次提交多列）；
- 批量修改/粘贴（Excel 式多单元格）、撤销（短时 toast）；
- 列过滤/排序、隐藏列、结果导出 CSV；
- 内联编辑支持更多类型（枚举、JSON 只读、二进制预览）。

### M2：查询治理与认证审计

- 查询结果行数上限 + 执行超时 + 手动取消（后端 `Statement.cancel`）；
- 导出结果（CSV），避免一次性加载大结果；
- SQL 安全校验重做：危险操作分级 + 二次确认，替代黑名单；
- 可选认证（Basic Auth / Token）+ 操作审计日志（谁在何时改了哪行）；
- 目标库集成测试引入 Testcontainers（MySQL/PostgreSQL）。

### 长期（非当前目标）

- 多用户/权限体系（与“本机单用户”定位冲突，若做需先改安全模型）；
- 主题/暗色模式、国际化；
- 插件式数据库方言扩展；
- 数据库表/数据对比、ER 图等高级功能。

## 3. 已知限制（当前版本）

- **无登录认证、无操作审计、无多用户权限**；默认仅本机访问；
- PostgreSQL 仅“测试连接”可用，浏览/编辑/查询按 MySQL 方言实现，尚不可用；
- 查询结果一次性加载内存，无行数上限/超时；大表请自行 `LIMIT`；
- 表分页 `COUNT(*)` 在超大表上较慢（规划估算/缓存）；
- 单元格编辑：仅单行单列；不支持批量/撤销；行标识列、自增列、BLOB/JSON/空间类型只读；
  无主键且无 `UNIQUE NOT NULL` 索引的表整表只读；
- 表数据编辑目前为 MySQL 方言（PG 待 P0-4）；
- CSV/Excel 导入要求表头与表列完全一致，不支持列子集映射；
- SQL 黑名单校验会误伤合法 SQL（`information_schema`、优化器 hint 等），且不是安全边界；
- 元数据库 H2 文件不支持多实例并发写同一 `data/`（单实例部署）；
- 前端暂无自动化 UI 测试（构建 + 手工清单为主）。

---

## 4. 设计原则（做取舍时优先）

1. **本机单用户优先**：不为了多用户/云化牺牲“一个 JAR 打开即用”；
2. **数据安全优先**：危险操作二次确认、编辑走参数化 + 乐观冲突、默认最小网络暴露；
3. **符合数据库工具心智**：资源树 + Tab + 表工作区，减少跨页跳转；
4. **MySQL 优先**：先保证 MySQL 完整可用，再扩展 PG；
5. **文档与实现同步**：每个里程碑更新 README/docs/CHANGELOG。
