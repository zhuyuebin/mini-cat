# MiniCat 前端信息架构重构方案（P0，开发契约）

> 状态：待开发 · 目标分支：`feat/ui-refactor`（基于 `feat/m1-correctness`）
> 本文是把「用户意图 → 产品结构」对齐后的定稿方案，实现与验收以本文为准。

---

## 0. 背景

当前前端是「三个独立页面各自管自己的状态」：

- 连接管理页点「选择」只写 Pinia，SQL 工作台 / 数据表管理并不读取，仍要各自再选连接；
- 表级操作与数据级操作混在一个工具栏，按钮随选中状态出现/消失/换行；
- 首页是营销页，不是工作台；
- 没有「连接 → 数据库 → 表」的路径感，切页丢上下文。

结论：问题不在单个页面，而在**信息架构**。本次重构目标是用「资源树 + 多 Tab 工作区」替换三个平级页面，让用户的心智模型（选连接 → 选库 → 选表 → 操作）与产品结构一致。

## 1. 目标与原则

1. **一次选择，全局生效**：资源树是唯一导航源，点哪里，工作区跟到哪里；任何页面不再重复选连接。
2. **操作跟着上下文走、位置稳定**：按钮不隐藏只置灰；高频动作 1 次点击，低频/危险动作收进「更多 ▾」。
3. **路径最短**：打开即工作台；恢复上次打开的 Tab/连接/库/表；空状态直接给「下一步」。
4. **连接类型是一等公民**：树与 Tab 都按「连接」抽象建模，不假设只有 MySQL；MySQL 与 PostgreSQL 连接可同时存在、可同时打开 Tab。

## 2. 信息架构

### 2.1 导航层级

```
应用外壳
├─ 顶栏：Logo | 数据目录/版本信息 | 设置 | 帮助
├─ 资源树（左）：连接 → 数据库 → 表
├─ 工作区（右）：多 Tab（表 / SQL 查询 / 欢迎）
└─ 状态栏：当前连接、类型、连接状态、最近刷新时间
```

### 2.3 路由

| 路由 | 说明 |
|---|---|
| `/workspace` | 默认首页：Tab 工作区（无 Tab 时显示欢迎/引导） |
| `/settings` | 设置（连接管理从一级导航迁入） |
| `/welcome` | 欢迎/帮助（无连接引导、产品说明） |
| 旧路由 | `/app`、`/connections`、`/query`、`/tables` 全部重定向到 `/workspace`（连接管理链接到 `/settings`） |

> **采用 Hash 路由**（`createWebHashHistory`）：`http://localhost:8888/#/workspace`。
> 原因：后端静态资源没有 SPA fallback，现在刷新 `/tables` 会 404；Hash 路由不需要改后端即可支持刷新/深链。P0 不改后端。

## 3. 多 Tab 工作区规格

### 3.1 Tab 类型与命名

| 类型 | 标题 | 是否可关 | 说明 |
|---|---|---|---|
| `table` | 表名（tooltip：连接 / 库 / 表） | 是 | 每个「连接+库+表」唯一 |
| `query` | `查询 1`、`查询 2`… | 是（有未保存草稿时确认） | SQL 工作区，可在 Tab 内切换连接/库 |
| `welcome` | 欢迎 | 否 | 无 Tab / 无连接时展示 |

### 3.2 打开 / 去重 / 关闭 / 上限

- 资源树**单击表** = 打开（或聚焦已存在的）表 Tab；首次打开默认「数据」子页。
- **双击表** = 打开/聚焦并强制切到「数据」子页。
- 同一张表（连接+库+表相同）不重复开 Tab，只聚焦。
- 关闭：Tab 上 `×`、鼠标中键、`Ctrl+W`；表 Tab 无脏状态可直接关；查询 Tab 有草稿修改时二次确认。
- Tab 上限默认 **12**，超出时提示先关闭；Tab 过多时横向滚动 + 右侧下拉列表。
- 右键 Tab：关闭 / 关闭其他 / 关闭右侧（P0 可选实现）。

### 3.3 每个 Tab 的独立状态

| Tab 类型 | 持久化字段 | 不持久化 |
|---|---|---|
| `table` | connectionId、database、table、subTab（data/structure/info）、page、pageSize | 行数据、列元数据（恢复后按需重新请求） |
| `query` | 连接/库选择、SQL 草稿文本、标题序号 | 执行结果 |

规则：

- 每个表 Tab 维护**自己的分页状态**，切 Tab 回来不重置页码。
- 切 Tab 只切换视图，不打断其它 Tab 的请求（并发请求上限 2，其余排队）。
- 恢复时**只立即加载当前激活 Tab**，其余 Tab 在激活时才懒加载，避免启动并发请求。
- 表 Tab 的数据加载失败：Tab 内显示错误 + 重试按钮，不弹全局错误。

### 3.4 持久化与恢复

- localStorage key：`minicat.workspace.v1`，结构：
  ```json
  {
    "tabs": [{ "id": "...", "type": "table", "connectionId": "...", "database": "usertest",
               "table": "user", "subTab": "data", "page": 2, "pageSize": 20 }],
    "activeTabId": "...",
    "expandedKeys": ["conn:test1", "db:test1/usertest"],
    "lastContext": { "connectionId": "...", "database": "usertest" },
    "pageSizeDefault": 20
  }
  ```
- 启动流程：加载连接列表 → 校验持久化 Tab 的连接/库是否还存在（失效 Tab 丢弃并提示）→ 恢复 Tab 外壳 → 激活上次 `activeTabId` → 懒加载其数据。
- 版本号不匹配（`v1` 变化）时丢弃旧数据，不阻塞启动。
- 提供「清空工作区状态」入口（设置页），避免持久化状态卡死。

### 3.5 快捷键

| 快捷键 | 行为 |
|---|---|
| `Alt+T` | 新建查询 Tab（默认继承当前上下文） |
| `Alt+W` | 关闭当前 Tab |
| `Ctrl+Enter` | 在查询 Tab 内执行 SQL |
| `Esc` | 关闭当前弹窗 |

> 说明：浏览器保留的 `Ctrl+T` / `Ctrl+W` / `Ctrl+Tab` 无法被页面拦截，因此实现采用 `Alt+T` / `Alt+W`；Tab 之间用鼠标点击切换。

### 3.6 跨连接 / 跨类型

- Tab 列表可同时混合 MySQL/PG 连接、多个库、多张表。
- 每个 Tab 标题 / 上下文栏显示连接类型徽标（MySQL / PG），避免用户混淆。
- 状态栏显示当前激活 Tab 的连接类型与连接状态。
- **PG 能力边界（P0）**：PG 连接可新增、可测试连接，但浏览能力尚未支持（见 §6 能力矩阵）；树节点展开时显示明确提示「PostgreSQL 浏览能力开发中」，不弹错误弹窗。

## 4. 资源树规格

### 4.1 节点与加载策略

- 连接节点：名称 + 类型徽标 + 状态点（●成功 / ○未测试 / ✕失败）。
- 数据库节点：展开时才请求 `GET /connections/{id}/databases`，结果缓存到 store。
- 表节点：展开数据库时才请求 `GET /connections/{id}/tables?database=`，**树里不显示行数**（避免 N+1 COUNT）。
- 失败节点：显示「加载失败，点击重试」，不阻塞其它节点。
- 展开状态持久化（`expandedKeys`）。
- 刷新：树顶部「刷新」按钮 = 清空缓存重新加载当前连接；单个连接右键「刷新」。
- 搜索框（P1，本轮不做）。

### 4.2 连接类型能力矩阵

| 能力 | MySQL（P0） | PostgreSQL（P0） | PostgreSQL（P0-4 后） |
|---|---|---|---|
| 新增 / 编辑 / 删除连接 | ✅ | ✅ | ✅ |
| 测试连接 | ✅ | ✅ | ✅ |
| 展开数据库列表 | ✅ | ❌（显示"开发中"） | ✅ `pg_database` |
| 展开表列表 / 表结构 | ✅ | ❌ | ✅（默认 public schema） |
| 表数据分页 | ✅ | ❌ | ✅（反引号→双引号） |
| SQL 查询 / DML | ✅（已有限制） | ❌ | ✅（同一套校验） |
| 建表 / 导入 / 删表 | ✅ | ❌ | 建表方言另做（后续） |

> 前端通过「连接类型 → 能力集」映射决定树节点/按钮是否可用（集中在一个 `capabilities.js` 常量里），后续接后端能力接口时只改这一处。

### 4.3 节点操作

| 节点 | 操作 |
|---|---|
| 连接 | 新建查询、测试连接、编辑、删除、刷新 |
| 数据库 | 刷新、复制名称、（P1：新建数据库、新建表） |
| 表 | 打开（单击）、数据（双击）、新建查询（预填 `SELECT * FROM table LIMIT 100`）、导入数据、删除表（危险，二次确认） |

危险操作统一样式：红色 + 二次确认；删除表/库不放在主工具栏。

## 5. 表工作区

### 5.1 上下文栏（固定高度，不跳动）

```
test1 › usertest › user      MySQL · 3 列 · 100 行       [刷新]  [更多 ▾]
```
- 「更多 ▾」：导入数据 / 新建表 / 删除表 / 自定义 SQL（危险项置红并二次确认）。
- 行数来自分页接口 `total`（准确、实时），不再用表列表里的过期 COUNT 值。

### 5.2 数据子页

- 分页条**固定在卡片底部**（flex 布局，不随行数沉底）；默认每页 20，可选 20/50/100/200。
- 行号**全局连续**：`(page-1)*pageSize + index + 1`。
- 顶部只保留数据级动作：`新增行`，行内 hover 出现 `删除` 图标（不占整列）。
- 刷新按钮：重载当前页 + 更新 total；切换 Tab 回来保留页码。
- 导入成功：关闭弹窗 → 切到「数据」子页 → 刷新 total → 跳到最后一页（方便看到新数据）→ toast 显示"总计/成功/失败"。
- 新增行/删除行成功：刷新当前页 + total；删空当前页且 page>1 时自动回上一页。
- 空表：显示"暂无数据 + 新增行/导入数据"按钮。
- 加载中：表格 skeleton；失败：行内错误 + 重试。

### 5.3 结构 / 信息子页

- 结构：沿用现有列信息（列名/类型/可空/键/默认值/自增/注释），顶部只有「刷新」。
- 信息：表名、注释、列数、行数（total）、所属库、连接类型；**移除**后端从未赋值的「创建/更新时间」两行。

## 6. SQL 工作区

- Tab 内顶部：连接选择 + 数据库选择（默认继承打开 Tab 时的树上下文，可临时切换）。
- 工具栏：`执行 (Ctrl+Enter)`、`格式化`、`清空`；危险语句（DELETE/DROP/TRUNCATE）保留二次确认。
- 结果区：SELECT 展示表格 + 行数/耗时；DML 展示影响行数。
- SQL 草稿按 Tab 持久化（刷新/重启后可恢复，不自动执行）。
- 连接为 PG 时：Tab 显示"PostgreSQL 查询能力开发中（P0-4）"占位，禁用执行（P0）。

## 7. 设置（连接管理迁入）

- `/settings` 页面：连接列表（新增/编辑/测试/删除），复用现有 Connections 页面逻辑。
- 所有连接类型的测试连接都可用；列表显示类型徽标。
- 提供「清空本地工作区状态」按钮（localStorage）。
- 数据目录信息展示（需后端接口，P1）。

## 8. 欢迎 / 帮助页

- 无连接时（`/welcome` 或工作区空态）：四步引导「新建连接 → 选择数据库 → 浏览表 → 执行 SQL」，主按钮直达设置。
- 有连接时：不强制展示，作为「帮助」入口保留（原 Home 的产品介绍内容迁到此页）。
- 不再作为默认首页。

## 9. 状态模型（Pinia）

```
stores/workspace.js
state:
  connections: []
  dbCache:      { [connectionId]: { databases, loading, error, loadedAt } }
  tableCache:   { [`${connectionId}::${database}`]: { tables, loading, error } }
  expandedKeys: []
  tabs: []               // §3.3 结构
  activeTabId: null
  treeSelection: { connectionId, database } | null
  pageSizeDefault: 20
getters:
  activeTab, activeConnection, tabsByType
actions:
  loadConnections(), refreshConnections()
  toggleConnection/expandDatabase/loadTables(force)
  openTableTab({connectionId,database,table,subTab}), openQueryTab({connectionId,database})
  closeTab(id), closeOthers(id), activateTab(id), updateTab(id, patch)
  restoreFromStorage(), persistDebounced()
```

- 持久化：store 订阅变化 → debounce 300ms → 写 `minicat.workspace.v1`；只写白名单字段（见 §3.4）。
- 删除连接时：关闭该连接下所有 Tab（提示用户），清理缓存与持久化。
- 连接状态变化（测试失败/成功）只更新状态点，不关闭 Tab。

## 11. 与后端边界

- **P0 后端零改动**：只使用现有 17 个接口（连接 CRUD/测试、库列表、表/列、查询、DML、分页、导入、建表/删表、池状态）。
- P0 已知限制（必须在 UI 上如实提示，不假装支持）：
  - PostgreSQL 浏览/查询能力未实现（P0-4）；
  - 查询结果仍一次返回，无行数上限（M2）；
  - 导入要求表头与表列完全一致（M2）；
  - 表列表无行数显示（避免 N+1，行数以 Tab 内 total 为准）。
- 后续若需要「数据目录」展示、数据库数统计等，再单独加后端接口（P1/P0-4）。

## 13. 验收清单

### 多 Tab
- [ ] 点表 1 → 开 Tab；再点表 2 → 新 Tab；回点表 1 → 聚焦不重复开；
- [ ] 双击表 → 直接进「数据」子页；
- [ ] 表 Tab 各自保持页码/子页，切换不重置；
- [ ] 查询 Tab 可多个、草稿互不干扰；`Ctrl+T`/`Ctrl+W`/`Ctrl+Enter` 生效；
- [ ] 关闭查询 Tab 有未保存草稿时确认；超过 12 个 Tab 时提示；
- [ ] 刷新浏览器 / 重启应用：Tab、激活 Tab、连接/库/表、每页条数、SQL 草稿恢复；失效连接对应 Tab 丢弃并提示。

### 资源树 + 多类型连接
- [ ] 同时存在 MySQL 与 PG 连接：两个节点都在、状态点正确、都能测试连接；
- [ ] MySQL 可展开库/表；PG 显示「浏览能力开发中」提示，**不影响** MySQL 使用；
- [ ] 展开失败有重试；刷新节点生效；展开状态刷新后恢复；
- [ ] 树选中项与激活 Tab 同步。

### 表工作区（上一轮问题的回归）
- [ ] 100 行数据：分页条始终可见，第 1/2/3… 页可翻；每页 20；total=100；
- [ ] 行号跨页连续（第 2 页从 21 开始）；
- [ ] 导入后自动切数据页 + 跳末页 + total 更新；
- [ ] 增删行后 total 与页码正确；空页自动回退；
- [ ] 表结构字段（可空/默认值/自增）正确；信息页无假数据行；
- [ ] 窗口缩放/窄屏下工具栏不重叠、不换行错位。

### 全局
